# 工業安全監測系統 2.0 — 安裝與維護說明

這份版本以使用者上傳的 `工業安全系統(1).zip` 為基礎調整，保留原有專案的 `.env`、資料庫及模型檔案；沒有重新訓練 YOLO、修改原始資料庫中的正式事件，或導入多攝影機同時辨識功能。

## 啟動與使用

1. Windows 解壓縮完整專案，避免路徑過長。
2. 已安裝 Python、Node.js 與必要套件的電腦，可在專案根目錄直接雙擊 `open.bat` 啟動 MediaMTX、FastAPI 和 Vite；首次安裝先執行 `install.bat`。
3. 雙擊 `stop.bat` 關閉系統，再重新啟動以套用 `.env` 變更。
4. 一般管理頁：`http://localhost:5173/supervisor/login`；工人畫面：`http://localhost:5173/client/monitor`。
5. 工程師維護頁：**`http://localhost:5173/engineering`**，需手動輸入網址，普通主管選單不提供入口。
6. 若前端尚未安裝套件，進入 `frontend` 資料夾執行 `npm.cmd install`；開發啟動指令為 `npm.cmd run dev`。

工程師頁面仍需要登入：`engineer` 和 `admin` 可以進入，`supervisor` 不可以。網址不公開顯示不是資安機制，權限由 FastAPI 的帳號角色檢查。

## 主要修改

- **左側列表選單**：辨識設定、系統狀態、環境設定 `.env`、語音警告音量、產生模擬事件、**資料庫管理**、資料備份。
- **獨立工程師模式**：從主管側欄移除「工程師維護」和「系統狀態」，停用舊 `/supervisor/engineering`、`/supervisor/system` 頁面路由。
- **模型不能在網頁更換**：移除前端上傳／啟用 UI 和後端模型上傳／啟用 API；只顯示目前模型的唯讀資訊。原 `.env` 中的模型路徑及既有模型資訊保留。
- **工程師環境設定**：由後端只允許指定欄位修改專案根目錄 `.env`。不顯示 Gemini API Key 或含登入資料的 RTSP 原始 URL，不允許修改管理員密碼或模型路徑，更新不會清除其他 `.env` 欄位。
- **語音音量**：從工人頁面移到工程師模式，由 SQLite `system_settings.voice_volume` 統一保存；工人頁面約每 15 秒更新設定。保留工人端的聲音啟用／關閉與喇叭測試。因瀏覽器自動播放限制，每個工人端需自己先按下「開啟」才可播報。
- **模擬事件**：可快速新增未戴安全帽／防毒面具／隔熱手套／模擬跌倒，也能自訂攝影機、ID、備註和是否已結束；提供最近產生的模擬事件清單及單筆刪除。
- **事件合併**：手動產生的模擬事件直接寫入 SQLite `events`，與真實辨識事件一起顯示、納入主管儀表板／統計分析／Gemini 報告，前端不再區分資料類別。內部的 `events.is_test=1` 只作為安全刪除來源識別，**不影響正式數據計算**。舊模擬資料同樣會被納入統計。手動模擬不會觸發真正的 YOLO、WebRTC 警告、語音警報或產生真實攝影機截圖。使用正式報告前請知悉統計包含模擬資料。
- **工程師資料庫管理（CRUD）**：新增「資料庫管理」列表選單，提供以下經核准的資料表操作：
  - `events`：搜尋、分頁、瀏覽、新增、修改、刪除。新增的人工事件直接進一般事件統計、儀表板與 Gemini 報告，不另分分類；內部來源欄位只供維護追蹤。更改審核狀態時會同步更新改善欄位。
  - `cameras`：搜尋、分頁、瀏覽、新增、修改名稱／位置／資料庫狀態、刪除；攝影機 ID 不允許修改，預設使用中的 `camera-01` 不允許刪除。已有事件關聯的攝影機不可刪除。
  - `audit_logs`：搜尋／分頁／唯讀，避免破壞稽核紀錄。
  - 不開放任意 SQL；不開放直接存取 `supervisors` 密碼雜湊、`sessions`、AI 對話等敏感表。帳號管理仍由 `admin` 專用功能處理。
  - 刪除操作需二次確認，且有截圖的事件需先走原有截圖刪除功能清理檔案。新增、修改、刪除會留下工程師／管理員的操作紀錄。
  - 新增攝影機只是改資料庫中的**攝影機中繼資料**，並不會直接建立新的 RTSP Worker 或啟用多攝影機同時辨識。
- **備份**：仍沿用原有資料庫與截圖 ZIP 備份功能，建議進行資料庫修改前先備份。

## `.env` 注意事項

網頁開放編輯的環境變數包括 `CAMERA_ID`、`CAMERA_SOURCE`、`AI_STREAM_ENABLED`、`AI_PUBLISH_URL`、`AI_STREAM_FPS`、`VIDEO_ENCODER`、`FFMPEG_PATH`、`VITE_MEDIAMTX_STREAM`、`VITE_CAMERA_ID`、`GEMINI_MODEL`、`GEMINI_API_KEY`。

- `CAMERA_SOURCE=0` 是第一台本機攝影機；RTSP 攝影機可用 `rtsp://...`。**目前一次只啟動一個來源**，尚未支援在 `.env` 新增 `CAMERA_2` 後自動同時辨識。
- `.env` 儲存後必須重新啟動 FastAPI 和 Vite 才能完全套用。
- `.env` 含管理員初始密碼、串流網址及可能的密鑰，**不可分享、公開或上傳 GitHub**。完整 ZIP 保留了你上傳的 `.env` 和資料庫，請自行妥善保管；單純更新現有安裝可優先使用無敏感檔案的差異修正包。
- 原始 WebRTC `camera01/whep` 若沒有人向 MediaMTX 發布 `camera01`，仍可能出現 404。本次改版未包含新增原始攝影機發布流程或多攝影機辨識。

## 更新既有安裝

1. 關閉系統 (`stop.bat`) 並先備份現有專案，尤其是 `.env`、`backend/safety.db*`、`backend/snapshots`、`backend/model`。
2. 如果只想更新程式，使用**差異修正包**，將其中 `backend`、`frontend` 的內容複製到原有專案相應位置並覆蓋。差異修正包不含 `.env`、原資料庫及模型。
3. 如果想使用**完整系統包**，解壓成新的專案資料夾使用；不要直接覆蓋有更新資料的原資料庫。
4. 適用的資料庫欄位 `events.is_test` 會在啟動時自動以非破壞性方式新增。
5. 如果進入工程師頁面白畫面，按 `F12` 開啟 Console，將第一個紅色錯誤訊息及後端錯誤日誌保存供排除。

## 測試與限制

- 後端：**22 項 pytest 測試通過**，包含舊有功能、角色權限、模擬事件合併統計、資料庫 CRUD／注入防護／關聯限制、音量 API、安全修改 `.env` 和模型操作端點已移除。
- 前端：使用 TypeScript 解析器對 **32 個 JS／JSX 檔案進行語法解析，沒有語法錯誤**。
- **前端完整 npm build 未驗證**：執行 `npm ci --offline` 時缺少 `yocto-queue` 依賴的本地快取。請在可連線網路的 Windows 電腦上執行 `install.bat`，之後正常啟動。
- **未在使用者的 Windows／攝影機／RTX 4050／MediaMTX／Gemini 真實環境實測**，不保證上述設備串流及外部服務正常運作。
- 此次修改不含多攝影機同時辨識、前端真正模擬 AI 警報／事件截圖，亦不包含重新訓練模型。

## 同一區域網路手機與電腦連線

1. 筆電執行 `open.bat`；前端必須監聽 `0.0.0.0:5173`，FastAPI 監聽 `0.0.0.0:8000`。
2. 在筆電的 CMD 執行 `ipconfig`，找目前 Wi-Fi/乙太網路的 IPv4 位址（例如 `192.168.1.105`）。
3. 其他裝置在同一個可互通的 LAN，開啟 `http://192.168.1.105:5173`。筆電 IP 請換成實際數值。
4. 前端會自動將 `.env` 中的 localhost / 127.0.0.1 API、WebSocket、WHEP 位址換成開啟網頁的筆電主機名稱；不需隨 IP 變動手動改三行環境設定。
5. 若網頁能開但無法登入，請先在手機試 `http://<筆電IPv4>:8000/api/health`。若無法連線，檢查 Windows 私人網路防火牆 TCP 8000 及 Wi-Fi 用戶端隔離。
6. 原始筆電攝影機 `CAMERA_SOURCE=0` 由 Python OpenCV 讀取，後端 MJPEG `/api/public/cameras/camera-01/stream` 可提供給其他裝置，不需另外讓 MediaMTX 發布 `camera01` 原始路徑。AI 串流優先嘗試 WebRTC，若無法連線則改走 `/api/public/cameras/camera-01/ai.mjpg`。
7. 如果採用 WebRTC，可能還需要 Windows 私人網路防火牆允許 TCP 8889 和 UDP 8189；影像若無法透過 WebRTC 連線，可先測試上面的 MJPEG 路徑。
8. 開放給同網路其他裝置不代表已完成外網安全防護。不要設定路由器連接埠轉發，請使用強密碼。

注意：MJPEG 是備援傳輸，無法保證與 WebRTC 一樣的低延遲及頻寬效率；實際裝置仍需測試。


## 多攝影機與區域網路更新（2026-10-19）

- 攝影機 01：筆電內建攝影機，預設啟用（來源 0）。攝影機 02：RTSP 網路攝影機，預設停用。
- 工程師在 `http://localhost:5173/engineering` → **攝影機管理** 可分別開啟／關閉及修改來源，不需要重啟後端。RTSP 密碼不會回傳前端。
- 只有開啟且 8 秒內有成功取得影格的攝影機才會出現在主管與工人畫面的下拉選單。停用後會停止讀取及 YOLO 辨識，也不再列於公開清單。
- 攝影機 02 的預設 RTSP 來源從專案根目錄 `.env` 的 `CAMERA_2_SOURCE` 首次匯入 SQLite。之後以工程師維護頁面的設定為準。若 RTSP 不連線，請核對設備實際 RTSP 路徑、port、裝置是否同網段及裝置端 RTSP 是否啟用。
- 每台攝影機有獨立的 YOLO/ByteTrack 追蹤狀態、事件、MJPEG、WebSocket 與標註串流（`camera01_ai`、`camera02_ai`）。多路同時啟用會增加 GPU 負載。
- 統計頁每日趨勢與違規時段改成含日期／小時 X 軸的圖；其他類別圖維持類別軸。
- 同 LAN 裝置使用筆電 IP 的 `http://<筆電IP>:5173` 連入。若網頁能開但登入無法使用，請確認 Windows 私人網路防火牆允許 TCP 8000，系統運行 `0.0.0.0:8000`。
- **安全提醒**：`.env` 及資料庫可能包含 RTSP 帳密與管理員資訊，不要將完整系統 ZIP 公開分享。
- 更新時先備份 `backend/safety.db`（含 WAL/SHM）、`.env`、模型，再覆蓋修正包，重新執行 `open.bat`。修正包不包含這些私有檔案。

## 驗證限制

後端既有測試已通過；本環境尚未實機驗證 Windows 筆電攝影機、指定 RTSP 設備、雙路 GPU 推論與手機瀏覽器。
